## Final Model Confirmed Against This Data

Per the clarified v4 model: customers enter the full prescription (SPH, exact CYL, AXIS, optional ADD); plus/minus CYL and AXIS are used **only** to normalize to canonical minus-cylinder notation; **after normalization, no further rule is applied based on the original CYL sign** — the original sign has already done its work through transposition. SE is calculated for reference only, never as the recommendation. The existing empirical band rules are unchanged.

**This data confirms the current implementation already matches that model exactly**, with no code changes required:

- Every row where the original CYL was written **minus** (or is 0.00): V4's result equals the OLD tool's as-written result exactly. Normalization was a no-op, as it should be.
- Every row where the original CYL was written **plus**: V4's result differs from what the OLD tool would have given that literal input — because the OLD tool would have (incorrectly) applied a rule based on the un-transposed plus sign, and V4 correctly transposes first. Rows 7, 10, 12, and 14 below demonstrate this directly, including two mathematically-equivalent-pair rows (12 and 14) that now match their minus-form counterparts (11 and 13) exactly.
- `+2.75/−1.25` and `+2.75/+1.25` (your example) are confirmed genuinely different prescriptions with different normalized SPH (2.75 vs. 4.00) — not accidentally collapsed together. No case in this dataset shows two non-equivalent prescriptions being incorrectly merged.

**No implementation bug was found during this validation pass. No calculator code was changed.**
